Module 1 — Foundations

💬 The Shell Prompt 1.2

[knox@fedora ~]$ ls
knox = username fedora = hostname ~ = $HOME directory $ = normal user   # = root

And this is what it looks like when you are root

[root@fedora ~]# █
WARNINGNever be in root. The prompt turns red in most configs and $ becomes # — that's the terminal telling you the safety is off. Every command runs with infinite privileges, nothing asks "are you sure", and one typo can end a filesystem. Use sudo for the single command that needs it, then go back to being mortal.

* Like, for example, you should never ever-ever type root into the terminal username field at the top of this website.

🗂 Filesystem Hierarchy Standard (FHS) 1.2

/ Root of the entire filesystem
├── bin Essential user binaries (symlink → /usr/bin on Fedora)
├── dev Device files — hard disks, USB, terminals as files
├── etc System-wide config files (plain text, editable)
├── home User home directories
│ └── knox Your personal files, configs
├── mnt Temporary mount point (USB drives etc.)
├── proc Virtual filesystem — running processes as files
├── root Home directory of the root user
├── tmp Temporary files — wiped on reboot
├── usr/bin Most user commands (ls, grep, etc.)
│ └── local/bin /usr/local/bin — system-wide extra software, root-only (NOT the same as ~/.local/bin below)
├── home/knox/.local/bin Your own scripts go here — user-only, already in $PATH on Fedora
└── var Variable data — logs, mail, databases

ls -ld /home/knox
sudo chmod 701 /home/knox  # x bit = can traverse, NOT list
1. Permissions checked per file individually
2. You are owner → use owner permissions and STOP
3. You are in group (not owner) → use group permissions
4. Neither → use other permissions
5. root bypasses ALL permission checks

SSH client (connecting from your machine)

CommandWhat it does
ssh <user>@<ip>Connect to a remote machine via password
ssh knox@192.168.1.151Example: connect as knox on that IP
exit or Ctrl+DEnd SSH session

SSH key authentication (recommended over passwords)

# 1. Generate a key pair on the CLIENT machine
ssh-keygen                   # default RSA 3072-bit (ED25519 on Fedora 40+)
# Keys saved to ~/.ssh/id_rsa (private) and ~/.ssh/id_rsa.pub (public)

# 2. Copy your public key to the server
ssh-copy-id -i ~/.ssh/id_rsa.pub knox@192.168.1.151
# This adds your public key to ~/.ssh/authorized_keys on the server

# 3. Connect — no password needed
ssh knox@192.168.1.151

# 4. (Optional) Disable password auth on server for security
# In /etc/ssh/sshd_config, change:
# PasswordAuthentication yes  →  PasswordAuthentication no
sudo systemctl restart sshd
TIPED25519 is the modern preferred key type (elliptic curve). Use it when available: ssh-keygen -t ed25519
WARNINGNever use SSH-1. It is fundamentally broken. Always use SSH-2 (the default in OpenSSH).
NOTEUse sudoedit instead of sudo nano when editing system files. It works via a temp file, protecting against corruption if something goes wrong mid-edit.

🔑 OpenSSL — Symmetric Encryption 2.1

# Check Camellia support
openssl list -cipher-algorithms | grep -i camellia

# Encrypt a file with Camellia-256-ECB
openssl enc -camellia-256-ecb -in message.txt -out message.enc -pass pass:MyPassword

# Verify it's encrypted (should say "data", not "ASCII text")
file message.enc

# Decrypt
openssl enc -d -camellia-256-ecb -in message.enc -out message_decrypted.txt -pass pass:MyPassword
NOTEECB mode is for demos only. Use CBC or GCM in real usage. Install OpenSSL with sudo dnf install openssl.

⚙ Systemd & Services 2.2

Linux boot process

1
BIOS/UEFI executes the Master Boot Record (MBR)
2
MBR executes the bootloader (e.g. GRUB)
3
Bootloader executes the kernel
4
Kernel executes /sbin/init — which is systemd (PID 1)
5
systemd executes targets — the systemd replacement for legacy SysV runlevels (not literally called "runlevels" anymore)
6
Target programs are executed — login screen appears

systemctl — Service management

CommandWhat it does
systemctl start <service>Start a service now
systemctl stop <service>Stop a service now
systemctl restart <service>Restart a service
systemctl reload <service>Reload config files without stopping the service
systemctl status <service>Check if a service is running and view recent logs
systemctl enable <service>Make service start automatically on boot
systemctl disable <service>Stop service starting on boot
systemctl list-unitsList all active/enabled services
systemctl list-units --allList all units including inactive
systemctl list-units --state=runningFilter by state (running, exited, etc.)
systemctl --user <subcommand>Manage user-level services (not system-wide)

Service files — anatomy

# Location: /etc/systemd/system/myservice.service
# User services: ~/.config/systemd/user/

[Unit]
Description=My Service Description
After=network.service      # start after this service

[Service]
ExecStart=/usr/bin/myprogram -a   # command to run on start
ExecReload=/usr/bin/myprogram -k  # command on systemctl reload

[Install]
WantedBy=default.target   # enable on normal system boot
NOTEService files for installed software go in /etc/systemd/system/. After creating or editing a service file, run sudo systemctl daemon-reload before starting it.

sudo -E crontab -e

# Example cron jobs:
# Every minute, log /etc to a file
* * * * *  ls -la /etc >> /var/log/etc.log

0 13 * * 1,4,6  cat /proc/uptime >> /var/log/uptime.log

*/15 * * * *  /path/to/script.sh

# Weekdays 08-16, every hour
0 8-16 * * 1-5  /path/to/script.sh

Mounting commands

CommandWhat it does
mountShow all current mount points

TIPIf you get "target is busy" when unmounting — you're probably cd'd into the mount point. Run cd ~ first, then unmount.

Persistent mount points — /etc/fstab

# /etc/fstab — each line = one mount point
# filesystem   mountpoint   type    options   dump  pass
UUID=bc979f3b-d4d2-47dd-aad5-ab4f1ac93345  /home/games  ext4  defaults  0  2

# Get the UUID of a device:
sudo blkid   # copy the UUID= value from the relevant device
NOTEAlways use UUIDs in /etc/fstab, not device paths like /dev/sda1. Device paths can change if a drive fails or moves; UUIDs stay constant. Try man fstab — config files have man pages too!
NOTEdump column: legacy backup-utility flag, almost always 0 today (anachronism). pass column: fsck check order — 0 = never check, 1 = root filesystem (checked first), 2 = all other filesystems.

📦 Archiving, Compression & Backup 3.1

NOTEArchiving = combining files into one (no size change — can even grow from overhead). Compression = reversibly shrinking size. Two separate operations, usually done together. Lossy (e.g. JPEG) discards data permanently — not the same thing as "compressed."

Compression utility comparison

ToolAlgorithmRatioCompress speedDecompress speedParallel variant
gzipLZ77Worst-ishFastFastestpigz
bzip2Burrows-WheelerMidSlowerWorst (up to 10× slower than gzip)pbzip2
xzLZMABestSlowest (scales -0…-9)Midpxz
zipCRCWorst——none possible (CRC can't be parallelised)
TIPPopularity in practice: gzip > bzip2 > xz > zip. zip is the only format here that archives and compresses in one step — tar needs a separate compressor.

tar — archiving

tar -cf archive.tar *              # create archive, no compression
tar -xvf linux-6.3.5.tar.xz       # extract — tar auto-detects the compression type
tar -tf archive.tar.xz            # list contents WITHOUT extracting
tar -czf/-xzf …  tar -cjf/-xjf …  tar -cJf/-xJf …   # gzip / bzip2 / xz shortcuts
tar -I <compressor> -cf out.tar.zst dir/  # arbitrary compressor via -I
WARNINGCourse material lists -a as the append flag. Real GNU tar disagrees: -a/--auto-compress auto-detects compression from the filename, and append is -r/--append (long form only, no short -a in most tar builds). Know the course's stated version for the exam, but don't rely on -a to append in a real terminal.

Standalone compression — gzip / bzip2 / xz

Data corruption & bit rot

WARNINGBit rot (mostly cosmic background radiation) is inevitable over time. Filesystems self-correct via Hamming codes — but only while mounted and periodically checked. Heavily compressed files are more fragile: compression removes redundancy, so a single flipped bit can irretrievably corrupt the file. Mitigate critical long-term storage with RAID 5 and frequent backups.

rsync — efficient backup & sync

Flag / syntaxWhat it does
rsync SOURCE DESTCopies only the diffs (delta transfer) — far cheaper than cp/mv for repeat backups
-aArchive — preserve permissions/attributes (a different meaning of "archive" than tar's)
-vVerbose
-hHuman-readable sizes
<user>@<host>:<path>Remote source or destination, over SSH
 
rsync -avh /Documents janrik@fedora:/var/company/backup   # local → remote
rsync -avh wizard@84.20.1.4:/etc/ /var/configbackup       # remote → local
TIPTrailing slash on the source path = copy the directory's contents. No trailing slash = copy the directory itself. Same convention applies later to Docker's COPY.
NOTESFTP, SCP, and rsync are all SSH-based transfer methods. SFTP = interactive session; SCP = simple one-shot copy; rsync = delta/incremental sync — best choice for repeat backups.

Backup scheduling — reasoning, not memorising

NOTEExam-style scenario: given business hours, power-off windows, and a ~1-2hr backup job, you're expected to reason about a safe cron window (e.g. after hours-close, before power-off), not recall one "correct" schedule. Know your cron syntax cold and think in terms of constraints.

A library is shared code reused by multiple programs; linking (the final compile step, connecting the program to its libraries) is the most common source of pain.

Copyleft vs. permissive vs. public domain — THE key distinction

ConceptDerivatives must stay free?Example
Public domainNo — anyone can appropriate it into proprietary softwareBrothers Grimm stories → Disney adaptations
CopyleftYes — this is copyleft's defining traitGPL
PermissiveNo — functionally equivalent to public domain despite the "open source" labelMIT, BSD, Apache
TIPCopyleft's "legal virality": the copyright holder keeps nominal ownership, but licence terms force every derivative to inherit the same licence — with no special revocation right, even for the original author (Linus Torvalds cannot revoke Linux's GPLv2 status).

Named copyleft licences

LicenceCan (all three)Distinguishing "must"
GNU GPLv3Use, distribute, modify, commercial useDisclose source, same licence, state changes
EUPL 1.2Use, distribute, modify, commercial useNo royalty, SaaS/network access counts as distribution, same licence
MPL 2.0Use, distribute, modify, commercial useDisclose source, lesser (file-level) copyleft only — weaker than GPL/EUPL

Permissive licence case studies

WARNINGMINIX → Intel ME: BSD-licensed MINIX (Tanenbaum) was folded into Intel's closed, undocumented Management Engine — present in every modern Intel CPU. No disclosure obligation under BSD meant no legal recourse. GPLv3 would have forced Intel to disclose ME's source.
WARNINGVS Code (MIT): "open-source" repo, but shipped binaries aren't copyleft — Microsoft can add undisclosed telemetry to what you actually download. Framed as "free labour": unpaid contributors work for Microsoft, not with them. Counter-example: VSCodium — same source, built without MS telemetry.
COURSEThe module states plainly it presents no counter-arguments and is "highly biased in favour of free software." A balanced exam answer should also weigh: commercial adoption ease, lower legal overhead for consumers, and stronger contribution incentives under permissive licences.

Classic exam traps

WARNINGWrong user context. Task fails silently or with "permission denied" because you're a normal user when it needs root — or you're root when the task says "as user X". Check the prompt: $ vs #.
WARNINGRelative vs absolute paths. A command that works in one directory breaks in another. When in doubt, pwd first and use absolute paths.
WARNINGSpaces and quoting. Unquoted spaces split arguments. Quote paths and patterns: "My File.txt", grep "two words" file.
WARNINGForgot daemon-reload. Edited a unit file and systemd is still running the old version. Reload, then restart the unit.
WARNINGForgot -r on directories. cp and rm need it for directories. Also: rm -r has no undo — read the path twice.

TIPUse man pages constantly. Expert admins do. You don't memorise commands — you recognise what problem needs solving and look it up. RTFM.
TIPBe careful with sudo. Before running a sudo command you found online, read and understand what it does first.
